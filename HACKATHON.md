### About the Hackathon

HackUMass is one of New England's largest collegiate hackathons, bringing together students from universities across the country to build innovative software and hardware projects.

Participants have 36 hours to develop a project, attend technical workshops, connect with industry sponsors, and compete for prizes.

The event welcomes college students of all majors and experience levels, including graduate students.

### Available Resources

- Technical workshops covering AI, cybersecurity, hardware, and software engineering
- Mentorship and assistance from experienced developers
- Hardware equipment, including Arduinos, Raspberry Pis, and other electronics
- Sponsor networking and recruiting opportunities
- Meals and designated rest areas
- Team-building activities

## 2. Our Target Sponsor Challenges

We are prioritizing two sponsor challenges.

### Capital One: Best Use of Nessie API

**Sponsor:** Capital One  
**Technology:** Nessie API  
**Award:** Best Use of Nessie

Nessie is Capital One's API platform for building applications around simulated banking data and financial operations.

#### Potential Applications

- Personal financial management
- Budgeting and expense analysis
- Transaction monitoring
- Financial accessibility
- Banking simulations
- Personalized financial planning
- Financial education

#### Our Objective

Develop an application where financial data and banking operations play a meaningful role in solving a real-world problem.

The Nessie integration should be a functional part of the application.

### Google: Best Use of Gemini API

**Challenge:** Best Use of Gemini API  
**Technology:** Google Gemini

#### Potential Applications

- Multi-agent AI orchestration
- Autonomous task planning
- Multimodal reasoning
- Document and image understanding
- Natural-language interfaces
- Personalized recommendations
- Intelligent workflow automation
- AI-assisted decision-making

#### Our Objective

Build an application that uses Gemini for meaningful intelligence, reasoning, or automation.

We are especially interested in multi-agent orchestration, where specialized agents collaborate to solve a larger problem.

### Combining Both Technologies

Potential architecture:

1. **Nessie API:** Provides simulated banking information and financial operations.
2. **Gemini API:** Performs analysis, reasoning, and agent coordination.
3. **Backend:** Handles business logic, calculations, API requests, and security.
4. **Frontend:** Provides an interactive experience and displays results.

We should choose the problem first, then determine how these technologies can meaningfully contribute.

## 5. Hackathon Rules

### Project Development

- Projects must be started after hacking officially begins.
- Creating or editing a project before the event can result in disqualification.
- Projects do not need to be completely finished to qualify for submission.
- Teams are encouraged to develop a functional prototype demonstrating their core idea.

### Team Size

- Teams of four or fewer are encouraged.
- Teams larger than four are permitted.
- Prizes for every member are not guaranteed for teams larger than four.

### Judging

- At least one team member must be present for judging.
- Judging begins Sunday at 12:30 PM.
- Project deliberation begins at 3:00 PM.
- Winners are announced during the closing ceremony.

The official website does not provide a detailed scoring rubric for every award.

### Conduct

All participants must follow:

- Major League Hacking (MLH) Code of Conduct
- UMass Amherst Student Code of Conduct

## 6. Project Selection Criteria

We will evaluate potential project ideas based on the following factors.

### Real-World Impact

- Does this solve a meaningful problem?
- Who experiences the problem?
- How serious or common is the issue?
- Can we demonstrate an improvement?

### Technical Depth

- Does the project involve meaningful engineering?
- Are the technical components necessary?
- Can we demonstrate real functionality?
- Is there enough complexity to distinguish the project?

### Originality

- Does the project address an overlooked problem?
- Does it offer something different from existing solutions?
- Is the approach creative or unexpected?

### Sponsor Integration

- Does Nessie contribute meaningful financial functionality?
- Does Gemini provide meaningful AI functionality?
- Can the two work together naturally?

### Demo Potential

- Can the problem be explained in 30 seconds?
- Can judges interact with the project?
- Can we demonstrate the solution in 90 seconds?
- Is the outcome immediately understandable?

### Feasibility

- Can we build a working prototype before the deadline?
- Can the main feature work reliably?
- Can we avoid unnecessary complexity?

## 7. Development Strategy

### Phase 1: Define the Problem

Identify:

- Target users
- The specific problem
- Why existing solutions are insufficient
- The consequences of leaving the problem unsolved
- What a successful solution would accomplish

### Phase 2: Define the MVP

Prioritize one core workflow that demonstrates the project's value.

Avoid unnecessary features or integrations that do not contribute to the main problem.

### Phase 3: Build

Development priorities:

1. Functional backend
2. Core API integrations
3. Working end-to-end functionality
4. User interface
5. Error handling and testing
6. Additional features, if time permits

### Phase 4: Prepare the Demo

The demonstration should communicate:

1. The problem and who experiences it
2. Why the problem matters
3. How our application solves it
4. A live demonstration
5. The technical architecture
6. The potential real-world impact

### Phase 5: Submit

Before the final deadline:

- Verify project functionality
- Confirm submission requirements
- Prepare the project description
- Document sponsor API usage
- Confirm team member information
- Test the live demonstration
- Submit before 9:00 AM EST Sunday
